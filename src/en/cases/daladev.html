DalaDev core design system

How we built the DalaDev Core Design System to speed up designers and developers and keep interfaces consistent across all products

Role
Design side of the design system
Type
Design system, tokens
Tools
Figma

Why did we need it?

At DalaDev we had a choice:

  • Use an existing design system
  • Build our own, tailored to our needs

Analyzing existing solutions showed that none of them covered our needs. So we decided to create DalaDev Core Design System — a universal multi-brand system to speed up designers and developers

Problems we solved

  • Duplicated work — standard elements were rebuilt for every project
  • No standards — fonts, styles and sizes needed constant recalibration
  • Poor file structure — components were badly organized
  • Inconsistent web and mobile design — web interfaces were poorly adapted

Goals

Unified UI kit

Create a unified UI kit based on design tokens

Flexible components

Build a flexible component system for all products

Training

Teach the team to work with tokens

Adoption

Build the system into development processes

Evolution

Maintain and evolve the system

02

Research

We studied open design systems:

  • Atomaro (Avito)
  • Material Design
  • Atlassian
  • Ant Design

We read many articles on how design systems work: Dodo IS by Dodo, OZI by OZON, Encore by Spotify, Lightning by Salesforce, Carbon by IBM, Base by Uber, Polaris by Shopify and Microsoft Fluent

Analysis criteria:

  • Token semantics — how they name their tokens and why
  • Token structure — nesting and complexity of token groups
  • Sizing scale — which units they break numeric values into, and how sizing scales relate to each other across categories
  • Whether there’s a base unit that sizes are calculated from, or sizes are set manually
  • Mobile and desktop tokens — whether they use Modes in variables or a separate file

03

Building the design side

Key steps

  • Audit and componentization of existing elements
  • A component library with variants and states
  • Design tokens (colors, sizes, typography)
  • Documentation and guides for the system
  • A presentation for the team — training on how to use the system

Extras

To speed up the work, we:

  • Adopted the ion icons icon font
  • Put together a universal set of neutral images for modals and empty states that works across all products
  • Unified interface copy (removed brand references, standardized the tone)
  • Optimized and standardized the sizes and aspect ratios of images used in the apps
  • Moved to a 4-pixel grid

04

Implementation in code

Developers built a JSON → Flutter converter. I tested handoff methods, ran design reviews and helped with implementation

Component flexibility

Most components (where applicable) are set up to work on both mobile and desktop screens. This is done with Modes in Variables, where we created two modes — mobile and desktop

Results

  • 58 components on design tokens
  • Universal adaptation for mobile and desktop
  • Modes in Variables for flexible scaling
  • Easier work for developers — interfaces are assembled like a construction kit

05

Use in products

The new system sped up work on Sandyq Prime, QR PAY and Chayla Group

  • Pana uses the system for new screens
  • Taza and Minmin were the first test products

Today developers and designers don’t build interfaces from scratch — they use ready-made components. This saves 90% of the time on routine tasks

06

Takeaways

  • DalaDev Core cut development time
  • Design became consistent across all products
  • The library file is kept up to date and maintained
  • Adopting the design system gave the team flexibility and predictability
