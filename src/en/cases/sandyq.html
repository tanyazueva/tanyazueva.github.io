About the project

Sandyq Prime is a loyalty program for guests of Sandyq restaurants, with or without a subscription. It offers exclusive perks: free drinks, higher cashback and personalized offers

Challenge

Design a mobile app that:

  • Increases customer loyalty to the chain
  • Reflects the style and atmosphere of the restaurants
  • Supports premium service principles for Sandyq and convenience for TARY
  • Increases the average check
  • Encourages repeat visits
  • Builds a long-term bond between the brand and its customers

The app had to meet the high expectations and standards of its audience and also strengthen the distinctive image of the Sandyq Group brand

For the business

More repeat visits, a higher average check and stronger customer loyalty

For customers

Restaurant visits become better value, more convenient and more enjoyable

For the business, this means higher profits and guest retention; for users, a new level of comfort and better deals

01

PRIME subscription

Offers a free drink, increased cashback and personalized promotions, which makes the program more attractive to users

02

QR menu

Customers scan the QR code on the table and land in a menu where they can see photos of the dishes right away. This lifts order conversion, since choosing is easier, and increases the average check

03

QR payment for orders

Every table has a unique QR code synced with the restaurant’s iiko system. Customers can pay for their order straight from their phone, which speeds up service and reduces the chance of errors

04

Discount promo code at checkout and referral promo code

Users share the app with friends and get bonuses for the customers they bring in. Bonuses can cover part of the next order

05

Table booking

Guests can now book a visit in the app, which makes planning easier (before, they had to contact the restaurant separately)

06

Visit review

We built a review flow to get guest feedback quickly and improve service quality

07

Design library

→ DalaDev core design system
This project reused the core design system we had built on earlier projects

We had only designed light interfaces before, but thanks to well-structured design tokens the switch to a dark theme was quick and painless. Developers simply loaded a JSON file with the updated tokens, which cut implementation time significantly

Adapting the design library:

  • Copying the Figma file with tokens, components and assets
  • Updating color tokens for the dark theme
  • Checking that they apply correctly in components
  • Customizing product cards for the project
  • Launching the library in a separate file for mockups

Typography and sizes stayed the same, but we tested the tokens for quick customization

As a result, adapting the interface took minimal time, and the design stayed consistent in both themes

Process

1. Research and analytics

  • Getting into the business: analysis of the loyalty model, the competitive market and restaurant guests’ preferences
  • User interviews: we studied how customers currently interact with the venue and what they expect from a loyalty program
  • Defining KPIs: the main success metrics were a higher average check, more repeat visits and user engagement

2. UX design

  • User journey map: we worked through the user’s path — from sign-up to placing an order
  • Prototyping: we built an interactive prototype and tested the main user flows
  • UX iterations: after testing, we made adjustments to improve usability

3. UI and development

  • Design system: we used an existing component library, which sped up the work
  • Dark theme: thanks to a well-thought-out token system, implementation was quick and painless for developers
  • Development support: I worked closely with the product manager and developers and made sure the UI was built correctly

4. Testing and launch

  • Usability tests: we tested with real users and collected feedback
  • Bug fixing: we smoothed out minor rough edges before release
  • Launch and monitoring: we tracked metrics, analyzed user behavior and suggested improvements

Bottom line: a systematic approach let us launch the app quickly, minimize errors and get high user engagement from day one
